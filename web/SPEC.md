# Nouveau Web — Spec

Desktop web client for Nouveau. Agreed with the owner on 2026-10-01. This file is the source of truth for scope; `PROGRESS.md` tracks state. Re-read both before continuing work in a new session.

## Product

- **Audience**: all Nouveau users, built to a "owner first" standard. Desktop only (no mobile-responsive layout). English only.
- **Core job**: a spreadsheet-like transactions table.

### v1 scope

- Login with email/password and Google OAuth (Supabase redirect flow), plus a signup page.
- Workspace switcher (switch only; creating workspaces stays on mobile).
- Transactions table
  - Opens on the current month with previous/next navigation (totals match mobile).
  - Date-range filter and search widen it to any period.
  - Filters: type, category.
  - Inline cell editing (date, description, category, amount), Notion-database style.
  - Side panel for the full record (currency, proofs).
  - Quick add: `N` or "+ New" inserts an empty row at the top; Tab moves through cells; Enter saves and opens the next row.
  - Multi-select with bulk delete and bulk change category.
- Multi-currency at full parity with mobile: currency field, `home_amount` computed from `exchange_rates` with the same logic as mobile, totals in home currency.
- AI category suggestion from the description via `/api/classify-description`, same behaviour as mobile.
- Receipt proofs: view and download only, in the side panel (`/api/proofs/:transactionId`).
- Summary strip above the table: income, expense, net, plus a collapsible category breakdown. Clicking a category filters the table. Totals follow the active filters.
- Category management (create, edit, delete, icon, colour).
- Profile and sign out.

### Behaviour

- Deletes disappear immediately with an Undo toast; the database DELETE is deferred until the toast ends (see Decisions, M4). Large bulk deletes ask first.
- Sync is TanStack Query refetch on window focus. No Supabase Realtime.

### Out of v1

Separate insights page, receipt scanning/upload, attaching proofs, workspace admin (members, invites, settings, create), subscriptions, Indonesian, dark mode, CSV import/export, command palette.

## Design

- Notion's layout: left sidebar, dense rows, thin 1px borders, no hard shadows.
- Nouveau palette: warm off-white background (`#FFF9EB`) and amber (`#F59E0B`) throughout. Source tokens: `../constants/colors.ts`.
- Light mode only, all colours as CSS variables so dark mode can be added later.

## Tech

- Self-contained app in `web/` with its own `package.json`, using Bun.
- Imports generated Supabase types from `../types/supabase.ts`. Copies the few pure utils it needs (no imports of Expo/React Native code).
- Vite + React SPA, TanStack Router, TanStack Query, Tailwind, shadcn/ui, TanStack Table.
- Same conventions as mobile: components render, logic in hooks, pure functions in `utils/`, Supabase only through React Query hooks.
- Env: `VITE_SUPABASE_URL`, `VITE_SUPABASE_KEY` in `web/.env.local` (gitignored). Same values as the root `.env.local`.
- Custom API: `https://goofy.nouveau.my.id`, sends `Authorization: Bearer <token>` and `X-Workspace-Id`. CORS already allows browser origins.
- Checks: typecheck, lint, Vitest for money and date logic only.
- Check Context7 for current library APIs before using them.
- Hosting: Vercel at `app.nouveau.my.id`.

## Decisions

Record non-obvious choices made during the build here, with the reason.

### M1

- **Supabase types are re-exported from `src/types/supabase.ts`** (a type-only re-export of `../../../types/supabase`). One relative path in one file; everything else imports `@/types/supabase`. Nothing outside `web/` reaches the bundle.
- **`src/routeTree.gen.ts` is committed** (and ignored by ESLint/Prettier). It is generated by the TanStack Router Vite plugin, so `tsc` on a fresh checkout would fail without it. This is what TanStack recommends.
- **Route guards run in `beforeLoad`, reading the session through the query cache** (`queryClient.ensureQueryData(sessionQueryOptions)`), with the query client passed in router context. The auth listener writes the session into the cache and calls `router.invalidate()` when the signed-in user changes, which re-runs the guards. This keeps Supabase behind React Query and avoids a flash of the wrong page. Authenticated pages live under the pathless `_app` layout route.
- **Cache clearing on sign-out lives in the auth listener** (on `SIGNED_OUT`), not in `useSignOut` as on mobile, so a sign-out in another tab is handled too. It also removes the stored workspace id.
- **Workspace resolution is derived, not imperative.** Mobile resolves the active workspace with effects that call Supabase directly and recover from stale ids. Web derives it from two queries (my workspaces, my profile): stored id if still a member, else `users.active_workspace_id`, else the first workspace (personal first). Same localStorage key (`active_workspace_id`) and the same write to `users.active_workspace_id` on switch. Difference: web does not null out a stale `users.active_workspace_id` on the server; it just ignores it.
- **Sign-up passes `emailRedirectTo: window.location.origin`** so the confirmation link returns to the web app (mobile sends none and falls back to the Supabase Site URL). The origin must be in Supabase's redirect allow-list or Supabase falls back to the Site URL. Sign-up also turns Supabase's silent "user with no identities" duplicate response into an "already registered" error.
- **Form errors are inline** rather than mobile's modal alert. No Apple button (it is disabled on mobile).
- **Hand-rolled sidebar instead of shadcn's `sidebar` block.** That block brings mobile sheets, cookies and collapse state we do not need for a desktop-only shell. shadcn primitives used: button, input, label, dropdown-menu, avatar (style `radix-nova`).
- **Theme**: `src/index.css` has a palette layer (values from `constants/colors.ts`) and a semantic layer (shadcn token names) that only references the palette; dark mode later is a `.dark` block reassigning the semantic layer. `--primary-foreground` is gray-900 because white on amber fails contrast. Borders and hover surfaces are translucent gray-900 rather than gray-200/100, which look cold on the cream background. Extra tokens: `income`, `expense`, `primary-soft`, `primary-strong`. Font is Inter (self-hosted via `@fontsource-variable/inter`), radius 6px.
- **ESLint, not the Vite template's new default (oxlint)**, to match the spec and the mobile app. TypeScript 6 / Vite 8 came from the current template.
- **The profile placeholder already has a Sign out button**, because browser verification needs it before M4.
- **Dev server is pinned to port 5173 (`strictPort`)** so the OAuth redirect origin is predictable.

### M2

- **Foreign-currency amounts are read-only in the table.** An inline amount edit writes `amount` and `home_amount = amount`, which is only right when `currency === home_currency`. Rows in another currency show the home amount plus the original amount and cannot be edited until M3 brings exchange rates. Their date, description and category are editable.
- **New rows follow mobile's add form**: `currency` and `home_currency` are the active workspace's `home_currency`, `home_amount = amount`, `user_id` is the session user, `workspace_id` the active workspace; a positive amount and a category are required, description is optional (stored as null when empty). The id is generated in the browser (`crypto.randomUUID()`) so the row can be shown optimistically; timestamps are left to the database.
- **Picking a category also sets the transaction's type** to the category's type (inline edit, bulk change and quick add). Mobile gets the same result by only offering categories of the chosen type. The Type column is therefore not editable on existing rows; the quick-add row has a switch that flips expense/income and clears a category of the other type.
- **Queries**: `['transactions', workspaceId, from, to]`, scoped with `.eq('workspace_id', ...)` and the same category join as mobile, ordered `date desc, created_at desc`. The `receipt_proofs(count)` join is left for M3. Results are paged in 1000s because PostgREST caps a response and a custom range can exceed it. Type, category and search filters are applied in the browser to the loaded period, so search never widens the period.
- **Month navigation clears a custom range**; a custom range needs an explicit Apply and replaces the month until cleared.
- **All three mutations are optimistic** (edit, delete, insert) against every cached list, roll back on error, and refetch once the last in-flight mutation settles. Ids are sent in batches of 100 to keep `id=in.(...)` URLs short.
- **Undo re-inserts the deleted rows with their original ids, fields and timestamps.** It cannot bring back receipt proofs if the database cascades them on delete; revisit in M3 when proofs are shown (a deferred delete would avoid it). The Undo toast appears once the delete has succeeded and lasts 6 seconds; bulk deletes of more than 20 rows ask first.
- **Amounts are shown in full, not compact** (`Rp1.250.000`, not mobile's `Rp1.3M` list format): a spreadsheet needs exact values. Digit grouping is `id-ID` as on mobile; the prefix and decimals come from the currency rather than mobile's fixed `Rp`/0 decimals.
- **Amount input parsing**: grouping separators are accepted (`15.000`, `1,250,000`). Zero-decimal currencies (IDR, JPY, KRW, VND) reject fractions instead of guessing. For other currencies a lone `.` is a decimal point, so `1.250` is 1.25, while `1,250` is 1250.
- **Date cells take typed input** (`YYYY-MM-DD`, or day-first shorthand `15`, `15/3`, `15/3/26`) with a calendar open underneath; focus stays in the input so Tab and Enter work in the quick-add row.
- **Quick add focuses the description**, since the date is prefilled (today, or the last date saved this session); Shift+Tab reaches the date. Tab order is date → description → category → amount. In the category cell, Enter picks the highlighted option when a search is typed and otherwise saves the row.
- **The category combobox is hand-built on shadcn's Popover, not `cmdk`/Command.** Command keeps its input inside the popup, which takes focus out of the row and breaks Tab; cmdk also cannot have its list in a portal away from its input. The same picker is used for the toolbar filter and bulk change.
- **TanStack Table is v9** (`useTable`, features registered explicitly). It provides sorting, selection and shift-click ranges; cells are rendered by a row component rather than column `cell` renderers, because they need editing state. No virtualization.
- **Category icons** come from the `ionicons` package, limited to the curated names in mobile's `constants/category-icons.ts` (`src/lib/category-icons.ts`); anything else falls back to a coloured dot.
- **Picking with the mouse in the quick-add row moves on**: a clicked calendar day focuses the description and a clicked category focuses the amount, which also closes the popover. Keyboard picks leave focus where it is (Tab already moves on). Inline editors commit on a pick instead.
- **Amount sorts by size, ignoring the sign** (`home_amount`), so "largest first" mixes income and expense. Left as built; a signed sort is a one-line change if the owner prefers it.
- **Optimistic rows that tie** (several unsaved rows on one date) show the newest on top, matching the server's `created_at desc` once the refetch lands.
- **The Amount header puts its sort arrow before the label**, so the label's right edge lines up with the amounts. The toast's Undo button uses the amber primary instead of sonner's dark default.
- **M2 browser verification** ran against the owner-created test account in the owner's signed-in Chrome (no credentials in the repo, which supersedes the `TEST_EMAIL` / `TEST_PASSWORD` note under Delivery). The Chrome window could not be resized, so it was checked at a 2324px-wide viewport, not 1500px.
- **Selection is kept by id.** Rows hidden by a filter stay selected but bulk actions only apply to rows currently in the table. Switching workspace resets filters, selection and the draft row.

### M3

- **The side panel is a non-modal side peek**, not a dialog: the table stays usable beside it and shows panel edits as they happen. The open transaction is `?tx=<id>` on the transactions route (opening pushes history, so Back closes it). The record comes from the loaded period when it is there; otherwise it is fetched on its own (`['transaction', workspaceId, id]`, scoped to the workspace), which covers a reload on another month and a date edit that moves the row out of the period. Escape closes the panel unless a field is being edited or a menu/dialog is open.
- **Panel fields reuse the table's cell editors and the same actions**, so there is one save path. Type is shown but not edited directly: it follows the category, as decided in M2. Home amount (with the rate the stored conversion implies) and the timestamps are read-only.
- **Mobile has no currency picker**: its form always creates in the home currency and only re-converts existing foreign rows on edit. Web adds the picker in the panel, offering mobile's `COMMON_CURRENCIES` plus the row's current currency. **The quick-add row has no currency selector**: its amount cell has no room for one and a conversion that can fail does not fit Enter-to-save; add the row, then set its currency in the panel.
- **Conversion mirrors mobile's edit form** (`use-exchange-rate.ts`, `use-transaction-form.ts`): USD-based rows from `exchange_rates`, newest on or before the transaction's date, cross rate = rate(USD→home) / rate(USD→currency); `home_amount = amount × rate`, **stored unrounded** as mobile does (only the display rounds). When no stored rate exists (or the lookup fails) an amount edit falls back to the rate implied by the row's existing conversion; with neither, the edit is refused with mobile's "rate unavailable" message.
- **Differences from mobile, on purpose**: web re-converts only when the amount, date or currency changes (mobile re-converts on every save of a foreign row, even a description edit). A date edit re-converts only if the new date has a stored rate. A currency change has no implied rate to fall back on, so it needs a stored rate; it keeps the amount, rounded to the new currency's decimals. Switching to the home currency sets `home_amount = amount`.
- **Foreign rows in the table** show the original amount (small, muted) next to the home amount; editing the cell edits the original amount. Sorting still uses the home amount.
- **Proofs** use the API's `url` directly, as mobile does (the API returns ready-to-load URLs). Images open in a lightbox; PDFs, HTML and anything else open in a new tab in the browser's own viewer. Download fetches the file and saves it under its filename; if the storage host refuses the fetch (CORS), it opens the URL in a new tab instead. **Not verified with real proofs** (the test account has none).
- **AI suggestion follows mobile's add-form rules**: 1s debounce, non-empty description that differs from the last one classified, categories loaded, never after the user picked a category for that row, errors ignored silently. Each new quick-add row starts "unpicked". Web additionally drops an answer that arrives after the description changed or the row was saved. **It does not run in the panel**: the panel only edits existing transactions, and mobile never classifies in edit mode (the existing category counts as chosen).
- **Undo and proofs**: still an immediate delete plus re-insert (M2). If the database cascades `receipt_proofs` on delete, undoing the delete of a row with proofs loses them. Not changed here; needs an owner decision (deferred delete).
- **Date-range picker** opens on the two months ending with the period shown (previous month left, current right).
- **M3 browser verification** ran in the owner's Chrome at a small viewport (about 784 CSS px wide; the window could not be made larger). `/api/classify-description` answered `400 No categories found for user` for the test account, so a suggestion being applied was not observed; the request, debounce and silent failure were.

### M4

- **Deferred delete (replaces M2's delete-then-re-insert).** Deleting hides the rows at once but sends nothing. Each delete is a batch in a module-level queue (`src/lib/pending-deletes.ts`) with its own 6 second timer and Undo toast; the DELETE goes out when the timer ends or the toast is dismissed. Undo just drops the batch, so the rows and anything hanging off them (receipt proofs) are never touched. Hidden rows are filtered out where the page reads its data, not removed from the query cache, so a refetch on window focus cannot bring them back, and the summary and row counts follow.
  - **A second delete does not flush or replace the first**: batches are independent, each with its own toast and Undo.
  - **Flushed** when the transactions page unmounts (navigating to another page, switching workspace: the page is keyed by workspace), before `signOut()` (which waits for the DELETEs to finish, because they need the session), and on `pagehide` (tab closed or reloaded).
  - **The `pagehide` flush is a raw `fetch(..., { keepalive: true })` to the PostgREST endpoint** with the access token read synchronously from the session cache. supabase-js looks up the session asynchronously before sending, which a closing page never finishes. It is the one Supabase call outside a React Query hook (`deleteTransactionsOnUnload` in `use-transaction-mutations.ts`); RLS applies as usual.
  - **The queue owns the timer, not the toast** (toast duration is infinite and it is dismissed by the queue). Sonner pauses its timers while hovered or while the window is unfocused, which would leave "deleted" rows in the database indefinitely.
  - If the DELETE fails the rows reappear with an error toast. Known gaps: a sign-out from another tab within the 6 seconds drops the pending delete (the rows stay), and after delete-then-reload the reloaded list can in theory race the keepalive DELETE and show the row until the next refetch.
  - The >20 rows confirmation is unchanged.
- **Deleting a category deletes its transactions (database cascade).** Found in browser verification: mobile's plain `DELETE` on `categories` succeeded for a category with a transaction and the transaction went with it (`transactions.category_id` cascades). Web sends the same DELETE as mobile, but the confirmation first counts the category's transactions in the workspace, says how many will be permanently deleted with it, labels the button "Delete category and transactions", and stays disabled until the count is known. There is no Undo for a category delete. **Owner decision needed**: whether the foreign key should be `RESTRICT` instead (mobile's only warning is "Are you sure you want to delete …?").
- **Category rules otherwise match mobile**: name required, trimmed, 50 characters, no duplicate check; new categories get the first palette colour and no icon unless picked; `user_id` is the session user and `workspace_id` the active workspace; default (`is_default`) and user-created categories are treated the same (mobile never reads the flag; web only shows a "Default" tag). An icon cannot be cleared once set, as on mobile.
- **A category's type cannot be changed on web.** Mobile's edit form allows it, which leaves the category's existing transactions with the other type. Web creates a category inside the Expense or Income group and keeps it there.
- **Category editing is inline**, Notion style, instead of mobile's form sheet: click the name to rename (Enter or blur saves, Escape cancels), click the icon or the colour to pick from a popover (a pick saves and closes), bin on hover to delete. "+ New … category" at the end of each group opens a draft row (Enter or the tick saves, Escape discards).
- **Icons**: the picker offers the same curated Ionicons names in the same groups as mobile (`src/lib/category-icon-groups.ts`, copied from `constants/category-icons.ts`), drawn from the `ionicons` npm package (the same glyph set that `@expo/vector-icons` ships), and stored as `Ionicons/<name>` exactly as mobile stores them. No Expo package is needed. A Vitest test fails if a picker name has no SVG. The `ion-icon` element's three CSS classes were added to `index.css`: without them the stroke-drawn icons (trending-up, link, at) rendered as blobs, a bug since M2.
- **Colours**: mobile's 39-colour palette (`src/lib/category-colors.ts`). The default categories use colours outside the palette; they are shown as they are, and picking a palette colour for one cannot be reverted to the original from the UI (same as mobile).
- **Summary strip**: income, expense and net of exactly the rows in the table (period, search, type and category filters), summed from `home_amount` and shown in the workspace's home currency. Income and expense are rounded to the currency's decimals first and net is their difference, because converted amounts are stored unrounded and the three figures would otherwise not add up (seen: 410.862,5 showing as 410.863 with a net one rupiah off).
- **The breakdown ignores the category filter** (it uses the period, search and type filter). Otherwise clicking a category would collapse the breakdown to that one row at 100% and there would be nothing else to click. The selected category is highlighted; clicking it again clears the filter. Totals still follow every filter.
- **Breakdown details**: expense by default with an Expense/Income switch; when the type filter is set, the breakdown follows it and the switch is disabled. Bars are scaled to the largest category and percentages are of the type's total, as in mobile's category bar list; no "Others" bucket. A share that rounds to zero shows "<1%". Open/closed is remembered in localStorage (`summary_breakdown_open`), closed by default.
- **Profile is read-only**: avatar (or initials), name, email, sign out. Mobile's settings screen has no way to edit the display name, so web has none either. Same fallbacks as mobile: `users.display_name` then the auth metadata `full_name`; `users.profile_image` then `avatar_url`.
- **Deploy config**: `vercel.json` pins install/build/output, rewrites every path outside `/assets/` to `index.html`, and sets `immutable` one-year caching on `/assets/*` and `must-revalidate` on everything else. Missing assets are deliberately not rewritten, so a stale chunk URL is a 404 rather than `index.html` cached for a year. The Vercel project needs "include files outside the root directory" on, because the build reads `../types/supabase.ts`. External setup steps are in `DEPLOY.md`; none have been carried out.
- **M4 browser verification** ran in the owner's Chrome with the test account. The tab was reported as hidden by the browser, so timers were throttled and toast/dialog exit animations lingered; request timing was read from the page's resource timing entries because the extension's network log missed the transaction DELETEs. Not exercised: sign out (by instruction; code path read only), the >20 rows confirmation, a failing DELETE, and the cascade warning's final wording for a category in use (the cascade itself was observed before the wording was written).

### Post-v1: bottom "+ New" row, amount formatting, one type filter

- **The table ends with a "+ New" row** (a full-width button, also in the empty and filtered-empty states; hidden only when loading failed). It opens the same quick-add draft at the bottom, in place of the "+ New" row; after a save the row goes to its sorted place and the next draft stays at the bottom, scrolled into view. Escape discards and returns focus to the "+ New" row. The toolbar button and `N` still open the draft at the top.
- **There is one draft with a position** (`top` or `bottom`), not two. Using the other entry point moves the draft with everything typed and focuses its description. A saved row that the current filters or period hide behaves as it did with the top draft (it is saved and simply not shown).
- **Amount fields group digits while typing** (`AmountInput`: quick-add row, inline amount cell, side panel). The field keeps a plain value (`2000000`, `12.5`) and shows it formatted, so what is saved and how it is parsed are unchanged. Separators match how that amount is displayed: `2.000.000` (id-ID) for amounts in the home currency, `1,234.56` (en-US) for foreign rows; no symbol inside the field. Logic and caret handling are pure (`utils/amount-input.ts`, tested).
  - A typed `.` or `,` is always the decimal point for currencies with decimals (grouping is automatic) and ignored for zero-decimal ones. Fraction digits are capped at the currency's; leading zeros are dropped; at most 15 whole digits.
  - Pasted text goes through `parseAmountInput` (`2000000`, `2.000.000`, `2,000,000`, `Rp 2.000.000`); a paste that is not an amount is refused and the field keeps its text.
  - Backspace/Delete on a grouping separator removes the digit beyond it, so the key always does something.
- **The breakdown has no Expense/Income switch of its own**; the toolbar's type filter decides. Expense or Income shows that type; All shows two labelled groups side by side (Expense, Income, each with its total), percentages and bar lengths relative to the group's own type. A type with no rows has no group. As before, the breakdown ignores the category filter (the picked category is highlighted among its neighbours rather than shown alone at 100%), clicking a category never changes the type filter, and totals follow the visible rows. The switch was React state only, so no localStorage key was removed; `summary_breakdown_open` stays.
- **Browser verification** ran on the test account at one viewport size (window could not be resized). Not exercised: the classifier applying a suggestion (it answers 400 for this account, as in M3), and the panel amount editor on a foreign-currency row (inline cell only).

### Post-v1: content container

- **One content column for Transactions, Categories and Profile**: centred in the area to the right of the sidebar, at most 1200px wide including the usual 24px side padding (1152px of content). The width is a single token, `--container-page` in `src/index.css`, applied through the `.page-container` class. Below that width nothing changes: full width with the same 24px padding.
- **Bands stay full width, their content is inset.** Title bar, toolbar, summary strip, table scroller, bulk-action bar and footer each span the main area and pad themselves in to the column, so the hairlines run edge to edge, the table still scrolls with the pointer anywhere over it and its scrollbar stays at the window's edge. The table's fixed columns are unchanged (date 128, category 208, type 104, amount 200); description takes the rest, 436px at full column width.
- **Categories and Profile keep their narrower widths** (768px and 448px) and start at the column's left edge, under the title.
- **The side panel docks against the column**, not the window's right edge, so the open row and the panel stay next to each other. On a window wide enough for both (main area of 2032px or more) the column does not move when the panel opens; on narrower windows the panel is at the window's edge and the column gives up the width, as before. The panel's width is the token `--container-page-aside` (416px, unchanged). The page's `aside` slot (`Page`) does the layout.
- The sidebar stays at the window's left edge and toasts stay bottom-right of the window.
- **Browser verification** ran on the test account at a 2447px-wide viewport only: the extension's window resize had no effect on the viewport, so laptop widths (1280, 1440) were not checked in a browser.
