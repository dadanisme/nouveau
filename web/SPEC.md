# Nouveau Web — Spec

Desktop web client for Nouveau. Agreed with the owner on 2026-10-01. This file is the source of truth for scope; `PROGRESS.md` tracks state. Re-read both before continuing work in a new session.

## Product

- **Audience**: all Nouveau users, built to a "owner first" standard. Desktop only (no mobile-responsive layout). English only.
- **Core job**: a spreadsheet-like transactions table.

### v1 scope

- Login with email/password and Google OAuth (Supabase redirect flow), plus a signup page.
- Workspace switcher (switch only; creating workspaces stays on mobile).
- Transactions table
  - Opens on the current month with previous/next navigation (totals match mobile).
  - Date-range filter and search widen it to any period.
  - Filters: type, category.
  - Inline cell editing (date, description, category, amount), Notion-database style.
  - Side panel for the full record (currency, proofs).
  - Quick add: `N` or "+ New" inserts an empty row at the top; Tab moves through cells; Enter saves and opens the next row.
  - Multi-select with bulk delete and bulk change category.
- Multi-currency at full parity with mobile: currency field, `home_amount` computed from `exchange_rates` with the same logic as mobile, totals in home currency.
- AI category suggestion from the description via `/api/classify-description`, same behaviour as mobile.
- Receipt proofs: view and download only, in the side panel (`/api/proofs/:transactionId`).
- Summary strip above the table: income, expense, net, plus a collapsible category breakdown. Clicking a category filters the table. Totals follow the active filters.
- Category management (create, edit, delete, icon, colour).
- Profile and sign out.

### Behaviour

- Deletes are immediate with an Undo toast; large bulk deletes ask first.
- Sync is TanStack Query refetch on window focus. No Supabase Realtime.

### Out of v1

Separate insights page, receipt scanning/upload, attaching proofs, workspace admin (members, invites, settings, create), subscriptions, Indonesian, dark mode, CSV import/export, command palette.

## Design

- Notion's layout: left sidebar, dense rows, thin 1px borders, no hard shadows.
- Nouveau palette: warm off-white background (`#FFF9EB`) and amber (`#F59E0B`) throughout. Source tokens: `../constants/colors.ts`.
- Light mode only, all colours as CSS variables so dark mode can be added later.

## Tech

- Self-contained app in `web/` with its own `package.json`, using Bun.
- Imports generated Supabase types from `../types/supabase.ts`. Copies the few pure utils it needs (no imports of Expo/React Native code).
- Vite + React SPA, TanStack Router, TanStack Query, Tailwind, shadcn/ui, TanStack Table.
- Same conventions as mobile: components render, logic in hooks, pure functions in `utils/`, Supabase only through React Query hooks.
- Env: `VITE_SUPABASE_URL`, `VITE_SUPABASE_KEY` in `web/.env.local` (gitignored). Same values as the root `.env.local`.
- Custom API: `https://goofy.nouveau.my.id`, sends `Authorization: Bearer <token>` and `X-Workspace-Id`. CORS already allows browser origins.
- Checks: typecheck, lint, Vitest for money and date logic only.
- Check Context7 for current library APIs before using them.
- Hosting: Vercel at `app.nouveau.my.id`.

## Decisions

Record non-obvious choices made during the build here, with the reason.

### M1

- **Supabase types are re-exported from `src/types/supabase.ts`** (a type-only re-export of `../../../types/supabase`). One relative path in one file; everything else imports `@/types/supabase`. Nothing outside `web/` reaches the bundle.
- **`src/routeTree.gen.ts` is committed** (and ignored by ESLint/Prettier). It is generated by the TanStack Router Vite plugin, so `tsc` on a fresh checkout would fail without it. This is what TanStack recommends.
- **Route guards run in `beforeLoad`, reading the session through the query cache** (`queryClient.ensureQueryData(sessionQueryOptions)`), with the query client passed in router context. The auth listener writes the session into the cache and calls `router.invalidate()` when the signed-in user changes, which re-runs the guards. This keeps Supabase behind React Query and avoids a flash of the wrong page. Authenticated pages live under the pathless `_app` layout route.
- **Cache clearing on sign-out lives in the auth listener** (on `SIGNED_OUT`), not in `useSignOut` as on mobile, so a sign-out in another tab is handled too. It also removes the stored workspace id.
- **Workspace resolution is derived, not imperative.** Mobile resolves the active workspace with effects that call Supabase directly and recover from stale ids. Web derives it from two queries (my workspaces, my profile): stored id if still a member, else `users.active_workspace_id`, else the first workspace (personal first). Same localStorage key (`active_workspace_id`) and the same write to `users.active_workspace_id` on switch. Difference: web does not null out a stale `users.active_workspace_id` on the server; it just ignores it.
- **Sign-up passes `emailRedirectTo: window.location.origin`** so the confirmation link returns to the web app (mobile sends none and falls back to the Supabase Site URL). The origin must be in Supabase's redirect allow-list or Supabase falls back to the Site URL. Sign-up also turns Supabase's silent "user with no identities" duplicate response into an "already registered" error.
- **Form errors are inline** rather than mobile's modal alert. No Apple button (it is disabled on mobile).
- **Hand-rolled sidebar instead of shadcn's `sidebar` block.** That block brings mobile sheets, cookies and collapse state we do not need for a desktop-only shell. shadcn primitives used: button, input, label, dropdown-menu, avatar (style `radix-nova`).
- **Theme**: `src/index.css` has a palette layer (values from `constants/colors.ts`) and a semantic layer (shadcn token names) that only references the palette; dark mode later is a `.dark` block reassigning the semantic layer. `--primary-foreground` is gray-900 because white on amber fails contrast. Borders and hover surfaces are translucent gray-900 rather than gray-200/100, which look cold on the cream background. Extra tokens: `income`, `expense`, `primary-soft`, `primary-strong`. Font is Inter (self-hosted via `@fontsource-variable/inter`), radius 6px.
- **ESLint, not the Vite template's new default (oxlint)**, to match the spec and the mobile app. TypeScript 6 / Vite 8 came from the current template.
- **The profile placeholder already has a Sign out button**, because browser verification needs it before M4.
- **Dev server is pinned to port 5173 (`strictPort`)** so the OAuth redirect origin is predictable.

### M2

- **Foreign-currency amounts are read-only in the table.** An inline amount edit writes `amount` and `home_amount = amount`, which is only right when `currency === home_currency`. Rows in another currency show the home amount plus the original amount and cannot be edited until M3 brings exchange rates. Their date, description and category are editable.
- **New rows follow mobile's add form**: `currency` and `home_currency` are the active workspace's `home_currency`, `home_amount = amount`, `user_id` is the session user, `workspace_id` the active workspace; a positive amount and a category are required, description is optional (stored as null when empty). The id is generated in the browser (`crypto.randomUUID()`) so the row can be shown optimistically; timestamps are left to the database.
- **Picking a category also sets the transaction's type** to the category's type (inline edit, bulk change and quick add). Mobile gets the same result by only offering categories of the chosen type. The Type column is therefore not editable on existing rows; the quick-add row has a switch that flips expense/income and clears a category of the other type.
- **Queries**: `['transactions', workspaceId, from, to]`, scoped with `.eq('workspace_id', ...)` and the same category join as mobile, ordered `date desc, created_at desc`. The `receipt_proofs(count)` join is left for M3. Results are paged in 1000s because PostgREST caps a response and a custom range can exceed it. Type, category and search filters are applied in the browser to the loaded period, so search never widens the period.
- **Month navigation clears a custom range**; a custom range needs an explicit Apply and replaces the month until cleared.
- **All three mutations are optimistic** (edit, delete, insert) against every cached list, roll back on error, and refetch once the last in-flight mutation settles. Ids are sent in batches of 100 to keep `id=in.(...)` URLs short.
- **Undo re-inserts the deleted rows with their original ids, fields and timestamps.** It cannot bring back receipt proofs if the database cascades them on delete; revisit in M3 when proofs are shown (a deferred delete would avoid it). The Undo toast appears once the delete has succeeded and lasts 6 seconds; bulk deletes of more than 20 rows ask first.
- **Amounts are shown in full, not compact** (`Rp1.250.000`, not mobile's `Rp1.3M` list format): a spreadsheet needs exact values. Digit grouping is `id-ID` as on mobile; the prefix and decimals come from the currency rather than mobile's fixed `Rp`/0 decimals.
- **Amount input parsing**: grouping separators are accepted (`15.000`, `1,250,000`). Zero-decimal currencies (IDR, JPY, KRW, VND) reject fractions instead of guessing. For other currencies a lone `.` is a decimal point, so `1.250` is 1.25, while `1,250` is 1250.
- **Date cells take typed input** (`YYYY-MM-DD`, or day-first shorthand `15`, `15/3`, `15/3/26`) with a calendar open underneath; focus stays in the input so Tab and Enter work in the quick-add row.
- **Quick add focuses the description**, since the date is prefilled (today, or the last date saved this session); Shift+Tab reaches the date. Tab order is date → description → category → amount. In the category cell, Enter picks the highlighted option when a search is typed and otherwise saves the row.
- **The category combobox is hand-built on shadcn's Popover, not `cmdk`/Command.** Command keeps its input inside the popup, which takes focus out of the row and breaks Tab; cmdk also cannot have its list in a portal away from its input. The same picker is used for the toolbar filter and bulk change.
- **TanStack Table is v9** (`useTable`, features registered explicitly). It provides sorting, selection and shift-click ranges; cells are rendered by a row component rather than column `cell` renderers, because they need editing state. No virtualization.
- **Category icons** come from the `ionicons` package, limited to the curated names in mobile's `constants/category-icons.ts` (`src/lib/category-icons.ts`); anything else falls back to a coloured dot.
- **Selection is kept by id.** Rows hidden by a filter stay selected but bulk actions only apply to rows currently in the table. Switching workspace resets filters, selection and the draft row.
